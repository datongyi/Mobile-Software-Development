## 能力覆盖

这些实验按难度逐步覆盖了移动应用开发中的主要能力：

- **界面与状态**：WXML/WXSS、ArkUI 声明式布局、数据绑定、条件渲染、主题和响应式布局。
- **用户交互**：输入、点击、滑动、Canvas 触摸、系统剪贴板、联系人、相册和文档预览。
- **内容应用**：新闻列表与详情、搜索筛选、收藏点赞、评论、阅读历史和用户资料。
- **游戏逻辑**：地图数据、碰撞检测、推箱规则、撤销栈、计时器、关卡解锁和本地进度。
- **计算引擎**：递归下降表达式解析、运算优先级、科学函数、角度模式、记忆和单位换算。
- **云端能力**：云函数身份校验、云数据库元数据、云存储文件、临时链接、分页查询和失败清理。

## 开发环境

实验 1—4、6 使用微信开发者工具 Stable；推箱子也是使用 Canvas 的原生小程序项目。实验 5 使用 DevEco Studio 6.x、HarmonyOS SDK 6.0.2（API 22）和 Hvigor 6.x。不同实验的基础库、SDK、AppID、包名和云环境配置以对应目录中的 `project.config.json`、`build-profile.json5` 或 README 为准。

建议环境：

- Windows 或 macOS
- Node.js 作为实验 6 本地测试环境
- 微信开发者工具（实验 1、2、3、4、6）
- DevEco Studio、Hvigor 和 HarmonyOS SDK（实验 5）
- 可选真机：用于验证相册权限、系统分享、联系人、横竖屏和音效等平台能力

## 如何运行

### 微信小程序（实验 1—4、6）

1. 克隆仓库并进入目标实验目录。
2. 在微信开发者工具中选择“导入项目”。
3. 选择该实验目录中包含 `project.config.json` 的目录。
4. 使用自己的 AppID；测试账号能否使用相关 API 取决于账号权限，实验 6 需使用已开通云开发且有访问权限的账号。
5. 点击“编译”，按该实验 README 的步骤体验功能。

```bash
git clone https://github.com/datongyi/Mobile-Software-Development.git
cd Mobile-Software-Development
```

实验 6 还需要开通云开发、填写自己的云环境 ID、创建 `photos` 集合并部署 `getOpenid` 和 `publishPhoto` 云函数。云函数部署必须包含 `wx-server-sdk` 及其锁定依赖，详细步骤见[实验 6 README](./实验6：微信小程序云开发/README.md)。

### HarmonyOS 计算器

用 DevEco Studio 打开 `实验5：鸿蒙开发入门及计算器开发`，等待依赖同步后选择模拟器或真机运行。构建、签名、设备测试和 ArkTS 单元测试说明见[实验 5 README](./实验5：鸿蒙开发入门及计算器开发/README.md)。

## 数据、账号与提交说明

- 各实验的本地缓存、新闻互动、游戏进度、计算历史和主题设置只属于当前运行环境，不作为跨设备同步数据。
- 实验 6 的云环境、AppID、数据库、云存储和云函数属于运行者自己的云资源，克隆后需要重新配置。
- `project.private.config.json`、开发者工具个人配置、签名文件、云端导出数据、用户上传图片和本机截图不应提交到公共仓库。
- 提交前请检查目标目录的 `.gitignore`，只保留源码、必要资源、配置模板、锁文件和可复现的测试。

实验 3 的用户资料和互动数据保存在本地，“分享到朋友圈”为模拟流程；实验 5 的历史、记忆值和主题只保留在当前运行状态中。实验 6 使用真实云端数据，当前未实现点赞、评论、搜索和关注。各实验中的同名能力应以各自说明为准。

## 测试与验证

实验 4 使用 Node.js 内置测试模块验证游戏逻辑；实验 5 使用 Hypium 验证计算引擎；实验 6 使用 Node.js 测试覆盖照片服务、页面行为和发布函数。具体入口见各项目文档和测试目录。

实验 6 可在安装 Node.js 后运行：

```bash
cd "实验6：微信小程序云开发"
npm test
```

本地逻辑测试不能代替平台验收。联系人保存、相册权限、相机、系统文档预览和实际微信分享等功能需结合模拟器或真机检查；云端上传还需确认存储文件和数据库记录均已生成。
